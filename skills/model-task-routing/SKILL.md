# 任务与角色路由

本技能是全局角色选择、任务拆分和整树并发的唯一入口。按任务选择 supervisor 直做、supervisor → 一个执行者，或 supervisor → 一个 lead → workers；不在其他 Skills 维护第二份模型映射。

## 实际配置来源

- 当前用户对话承担 supervisor，使用其已运行的实际会话配置。新任务默认配置及可用角色由当前 Codex 环境决定；目录里有某个配置文件或编辑 Skill 本身，不证明它已加载。配置发现和接入方式见[Codex 配置接入参考](references/codex-setup.md)。
- supervisor 决定用户目标、范围、授权和最终验收。角色配置只表示预期配置；已运行的会话或执行者的实际模型仅按本轮可得运行元数据等证据确认。复用有效证据，不为回执重复重型诊断。
- 需要对多个工作包持续协调、拆工与集成时，supervisor 派遣一个 `lead`，并核对当前工具中 `lead` 角色已注册的配置与实际绑定。角色职责和选择依据只维护在本技能。
- explorer、planner、implementer、complex_implementer、reviewer、specialist、escalation 和 worker 等命名角色的预期模型与档位来自当前环境已注册的角色配置，Skills 只定义职责，不重复型号或档位映射。文件路径约定及 `[agents.<role>].config_file` 的核对方式见[Codex 配置接入参考](references/codex-setup.md)。
- 当前工具原生支持所需 `agent_type` 时，先核实该原生角色实际绑定的模型与档位是否和已注册配置一致；角色同名本身不证明配置相符。确认相符才直接使用原生入口。绑定不符或未知且本次要求特定配置时，只有在工具支持显式覆盖的情况下，才改用通用派遣并传入已核实配置中的 `model` 和档位（工具参数若叫 `reasoning_effort`，传入对应档位值）；不支持覆盖时报告能力缺口，不静默替换。工作包仍需携带角色必要职责；提示词写角色名、继承完整历史都不能代替真实绑定。
- 派遣前核对本次要求、项目规则、实际角色配置与当前工具能力。工具不支持要求的模型/档位时报告能力缺口，不静默换配置；当前执行者能力不匹配按下方纠偏机制及时处理。项目、专项流程和用户指令中更严格的模型、权限、工作区或审查上限继续有效。

## 是否派遣与整树并发

- 以剩余工作和可拆分性为主判断：一个不可合理拆分的连续工作包交给匹配角色完整交付；多个工作包需持续协调、拆分和集成时由一个 lead 统筹。先识别写入冲突、覆盖关系、共享资源和必要前置依赖，所有已就绪且可安全隔离的包优先并行，依赖只串行受约束的阶段。不要因为一个角色也能依次完成全部工作，就把可并行包排成串行。已做分析、决定和证据随工作包交接，避免下属重查。
- 问答、单次查询/调用或极小任务，先把派遣、上下文重建、等待和集成的完整交接成本算进去；当前会话可直接回答或完成且增加角色没有实益时，就由 supervisor 直做，不新建空 lead 或额外执行者。是否直做仍按当前任务与真实配置判断，不能只凭“简单”、强耦合、顺序依赖、上下文充分或读过材料下结论。
- 重要产品或技术取舍由 supervisor 先判断；结论和执行边界明确后，再交给匹配的执行者。剩余工作为单个不可合理拆分的工作包时不增加 lead 层。
- 执行角色按判断难度、失败代价和预计返工选择，不按“复杂”标签或改动量升级。已定的复杂多文件实现可继续交职责匹配的 `complex_implementer`，型号依角色 TOML；持续疑难判断交 `specialist`，多个工作包需要持续协调才用 `lead`，不为升级而新建空 lead。
- 只有多个工作包需要持续协调、拆工与集成时，同一工单才派一个 lead。lead 可自行完成或协调 workers；workers 不再派生角色，不创建嵌套 lead。
- 派遣人数和批次不设人为固定上限，按已就绪且可安全隔离的工作包，以及工具真实容量和适用权限、费用、用户/项目限制动态决定。先并行处理当前可安全执行的包；只有必要依赖、写入冲突或共享资源约束的相关阶段才串行。单个工作包若不可合理拆分，保持完整交付。
- 分配 workers 前核对当前工具报告的全局并发上限与实际空闲槽位，并扣除整棵任务树中仍占用容量的 lead、workers、reviewer 或其他派遣角色。所有层级共享这份容量，不各自再取一份上限；工具显示的状态优先，不能仅凭任务完成回执推断槽位已释放。整树并发不能超过工具上限、当前实际空闲容量或适用的用户/项目上限中的任何一个。无法确认剩余容量时减少并发或顺序执行。
- 判断是否派遣时结合剩余工作轮次，以及当前与候选角色真实可核对的模型/能力差异；不能仅因 supervisor 身份推断主线程昂贵，也不按命令数或运行时长机械分流。模型成本未知时不声称节省或成本优势。需要权衡时只比较与当前任务相关的总耗时、token、交接、等待与集成，不做无关调查，也不为省成本降低完成标准。较轻模型或档位只作为当前工具确实能执行的候选，须在相同输入与验收标准下比较，并和材料压缩、交接变化分开；不为单次试验修改默认配置或新建同义角色。细节见按需读取的[角色配置与计量参考](references/model-guide.md)。
- 先统一共享规则、接口和写入归属，再拆成最小但可完整验收的工作包；说明目标、负责路径、已定结论、本轮差量、必要原文的文件与章节/行号、授权和安全边界、禁止改动、验收及证据回执。保留判断所需依据，不复制无关历史，也不靠精简交接排除平台自动注入或必读上下文。协调者交付完整目标与边界，不预先逐行设计再要求执行者照抄；边界内实现细节由执行者判断。多人不得同时改同一核心文件。
- 独立 reviewer 只读。需要独立审查时由 lead（未派 lead 则 supervisor）按风险派遣并承担最终处理，不能绕过单一指挥链；reviewer 及其他正在运行的派遣角色同样占用整树工具槽位。

## 角色职责

每个阶段都按当前完整目标和剩余工作重新选职责，不沿用已结束阶段的难度或角色升级结论。脚本可确定的数字、状态等事实先用脚本核对；explorer 能抽取和定位事实，但不能单独裁判跨轮目标、冲突或语义结论。需要语义判断时按工作交给 planner、reviewer 或 specialist。

| 角色 | 负责内容 |
|---|---|
| supervisor | 当前用户对话；确定目标、范围、授权、是否派遣和最终验收。按剩余工作决定直做或派执行者；派 lead 后负责目标、授权、纠偏与最终核对，不重复下属的整套调查、实施和验证，也不越级向 worker 派工或纠偏。 |
| lead | 多个工作包需持续协调时的唯一执行负责人；持续调查、规划与拆分，统筹 workers 的实施和集成，在整批实现完成后统一 Verify、Review。遇到超出已定边界的重要取舍时交回 supervisor。 |
| explorer | 有界只读调查、查找证据和定位实现。 |
| planner | 将未定事项整理为选项、依赖、顺序和可执行计划；必要业务选择仍由用户确认。 |
| implementer | 执行已定、边界明确的实现、文案或配置工作；按要求整理已确认内容。 |
| complex_implementer | 执行已定的复杂或跨模块实现；只在角色配置与当前工具确实可用时选用。 |
| impeccable_asset_producer | 按已批准视觉方向制作可复用图片素材；只用于角色配置匹配的素材任务。 |
| prompt_writer | 撰写或改进普通提示词；按剩余工作与工具路径决定是否作为单一执行者。 |
| reviewer | 对已 Verify 的目标与证据做独立只读核对，返回具体问题、原因和修正要求；小任务不强制独立 reviewer。 |
| specialist | 疑难根因或复杂技术判断。 |
| escalation | 仅在 specialist 仍无法解决或达到既定升级条件时，整理证据和可执行方案后交回 lead/supervisor 落地；不持续管理或机械实施。 |
| default | 没有更合适专用角色时，使用 agents 默认配置。 |
| worker | 仅当工具只提供通用 worker 类型时作为兼容入口；按实际职责读取对应 TOML 并绑定配置。 |

先选职责再确定可并行工作包。普通设计或提示词由 supervisor 先明确重要取舍；单次小改可直做，多轮单包工作按边界和工具路径直派匹配角色；困难问题用 specialist；多个包需持续协调时用 lead。人数随就绪包和真实容量确定，不因固定人数目标强行拆工，也不把可安全隔离的包压成串行。

## 线程复用、纠偏与等待

- 仅复用上下文有效、真实角色与配置匹配、项目/路径和工作范围相符、无冲突占用且可安全继续的线程。需确认它在指挥链中的实际位置，并权衡保留有效证据的价值与加载无关历史的成本；标题相似、历史长或主题相关都不够。
- 复用已有用户对话仍须满足当前工具要求的消息授权；普通实施授权不自动授权跨对话派单。内部拆工不创建用户侧栏任务；工具或权限不支持时在现有授权范围内继续可完成的工作，不另建对话绕过边界。
- 直派时 supervisor 直接纠偏或停止执行者；已派 lead 时由 lead 统一传达，不越级重复指挥。紧急停止沿实际指挥链立即传达，负责协调的 lead 或 supervisor 核对所有下属的停止状态及已发生的副作用；未确认项明确标未知，不能假报整树已停止。已运行的实现模型不会因对话设置、角色配置或 Skill 文本更新而切换。
- 对具体执行失败先做一次有依据的定向修正；同类问题仍未解决，就报告 lead 诊断根因与接续路线，不盲目重复。能力与任务一开始明显不匹配，或定向修正后仍重复同类判断失败时，lead（未派 lead 则 supervisor）区分缺上下文、目标/验收不清、机械执行错误、工具/环境或权限限制，再判断是否确为推理能力不足。材料与标准充分但仍无法正确处理必要推理时，按角色职责和真实配置选择更适合的模型或思考档位接手；不要用稳定档位要求困住不匹配的执行者，也不必等满三次盲试才升级。命令误用、编辑锚点错误、缺少上下文/工具/权限或外部生成质量不佳本身不能证明 Codex 算力不足。
- 升级在同一任务指挥链内进行：停止或隔离原执行者的冲突写入，交接失败证据、已完成改动、授权与验收标准，由新执行者接手；换模型/档位不清零失败计数，不扩大专项上限、费用或权限。仅在实际角色默认长期不匹配且有依据时更新对应 TOML，不普遍抬档；改配置不会热切换旧会话。核对新执行者可得运行元数据，分别记录预期与实际模型/档位、调整理由及结果；无法核实时标未知，不冒称升级已生效。
- lead 等待 workers 时，先做不依赖其结果的授权主线；supervisor 只处理目标、纠偏、授权和必要回报，不重复 lead 的调查、实现与全套验证；无待处理事项后优先用工具原生 wait/join/完成事件等待。无原生事件能力才用有界稀疏 sleep 作为备用；sleep 不保证由子任务完成唤醒。不得用固定 10 分钟循环或高频轮询；遵守单次工具等待上限和进展汇报要求。
- 每个执行角色回报改动路径、实际检查结果、关键判断、缺口及阻塞。执行者或 lead 的 PASS 仍需由 supervisor 根据实际产物与证据完成整体验收。

## 上下文与证据成本

- 交接使用最小完整工作包，不复制全段聊天或已读日志；保留当前目标与阶段、路径、已定结论及差量、必要授权与安全边界、验收和证据入口，并为关键依据提供可定位的原文。接手者按需读原文；摘要不能代替关键依据核验。平台自动注入或要求读取的上下文仍须遵守。
- 先检索再读取，工具输出保留命中片段、失败摘要和证据路径；完整日志保存在适当位置。输出截断或过滤不得掩盖错误、退出状态或关键上下文，出现疑点再展开。
- 同一任务优先复用匹配且上下文有效的线程；后续只发变化。不因已有线程就加载无关历史，也不为省上下文丢掉恢复所需信息。
- 通用规则保持单一正文与明确触发入口；已读取且未变化的规则和证据复用，不重复整段加载。不删减始终适用的安全/授权要求，也不声称能通过 Skill 排除平台自动注入的上下文。
- 回报以完成、阻塞、实质变化和必要进展为主，不反复催问或复述。复验与独立审查按落地执行的证据和风险标准，不每层重做全套。
- 需要比较效果或成本时按同一任务、版本、输入和验收口径核算整棵任务树的输入、输出、耗时、返工、重试、交接、等待、Review 与结果。缓存输入是总输入的子集，推理用量是总输出的子集，不重复相加；父子统计是否重叠不明时分开列出，不合计。记录任务/turn 边界、数据截止时点、计量窗口，以及发生的压缩或重置；计数协议不明时不拼接快照或推断累计值。成本口径见[角色配置与计量参考](references/model-guide.md)。便宜型号、低档位或更短输出不证明任务总 token 或成本下降；没有可靠对照就不报节省比例，也不为收集指标另建后台任务。
